# FitForge — agent guide

FitForge is a **native SwiftUI** workout tracker with a 1930s **Chrysler Building Art Deco** look (brass-on-cream, sunburst spires, square corners). This file is the orientation for agents adding features or changing the UI. Read it before touching code.

## Hard constraint: no paid Apple Developer account, ever

The app is distributed by **sideloading via SideStore** (free Apple ID, 7-day re-sign). CI produces an **unsigned** IPA; SideStore signs it on-device. Because of this:

- **Never** add anything that needs a paid signing identity or special entitlements: push notifications, HealthKit, CarPlay, iCloud/CloudKit, app groups, Sign in with Apple, background modes requiring entitlements, associated domains, etc.
- No TestFlight / App Store assumptions. Keep the app self-contained and offline.
- Data persistence stays **local** (UserDefaults today — see `AppStore`).

## Branches

- **`swift-native`** — the active native SwiftUI app. **Work here.**
- `dev` — older Tauri 2 wrapper of the original web app (not active).
- `main` — original single-file PWA / earliest state (not active).

If you're building features, branch from `swift-native`.

## Project layout

The app lives in `FitForge/`. The Xcode project is **generated by xcodegen** from `FitForge/project.yml` and is **gitignored** — never edit `FitForge.xcodeproj` or `Info.plist` by hand; change `project.yml` and regenerate.

```
FitForge/

  Sources/
    FitForgeApp.swift          @main; injects AppStore, tints brass
    Models/
      Exercise.swift           static exercise catalog + muscleGroups; Exercise.byId / .cues
      Workout.swift            Workout / ExerciseEntry / SetEntry / PersonalRecord; AppDate; formatTime
    Store/
      AppStore.swift           @MainActor ObservableObject; persists workouts (UserDefaults "fg_workouts"),
                               derives PRs / weeklyVolume / streak; owns `active` session; seeds demo data
      ActiveWorkout.swift      @MainActor ObservableObject; elapsed clock + 90s rest timer (restDuration)
    Views/
      Theme.swift              ★ design tokens: `Deco` palette + Color(hex:) + Font.display/bodyText/mono
      Ornaments.swift          ★ Spire, StepCrown, DiamondDot, HatchFill (Canvas/Shape art)
      Components.swift         ★ shared UI: Tab enum, DecoHeader, Kicker, SectionTitle, decoCard,
                               DecoSearchField, MuscleChips, ChryslerTabBar, FlexibleWrap (Layout)

      HomeView.swift           dashboard: stats trio, Begin-Session CTA, recent sessions, records
```

The original design spec lives in `design_handoff_fitforge_chrysler/` (see its `README.md` + `FitForge Redesign.html`). It is the canonical reference for the visual language — consult it when in doubt about a screen.

## Build & run

```bash
cd FitForge
xcodegen generate          # regenerate the .xcodeproj after ANY project.yml change

# Simulator build (fast, no signing):
xcodebuild -project FitForge.xcodeproj -scheme FitForge -configuration Release \
  -sdk iphonesimulator -derivedDataPath build-sim CODE_SIGNING_ALLOWED=NO build
```

There's an iPhone 16 simulator already created for screenshots. For a device IPA, CI does it on tag — you rarely need to build device IPAs locally.

## Design system — follow it exactly

All visual tokens come from `Theme.swift`. **Never hardcode colors or font names** in views; use `Deco.*` and `Font.display/bodyText/mono`.

**Palette (`enum Deco`):** `cream` (bg) · `paper` (cards) · `ink` (text/dark surfaces) · `inkSoft` (secondary text) · `brass`/`brassDeep`/`brassLight`/`gold` (accents) · `line`/`lineSoft` (hairline borders) · `restTint`. New colors → add a token to `Deco`, don't inline `Color(hex:)` in a view.

**Typography:**
- `Font.display(size, weight)` — **Cinzel**, all-caps Roman serif. Titles/headings. Always add `.tracking(...)` (letter-spacing) and usually `Deco.ink`.
- `Font.bodyText(size, weight)` — **Inter**. Body copy, inputs.
- `Font.mono(size, weight)` — **DM Mono**. Kickers, labels, metadata, numbers — render **UPPERCASE** with `.tracking(2–4)`, usually `Deco.brassDeep`.

**Rules that make it look Deco — keep them:**
- **Square corners only.** Use `Rectangle()` strokes/fills; never `RoundedRectangle`/`cornerRadius`.
- **1px hairline borders** in `Deco.line`. Cards = `Deco.paper` + `Rectangle().stroke`. Use the `.decoCard()` modifier.
- **Kickers** above titles: short uppercase mono in brass (`Kicker`).
- **Screen headers** use `DecoHeader` (Spire crown + Cinzel title tracked ~6 + mono sub-kicker).
- **Section headers** use `SectionTitle` (kicker + `DiamondDot` + Cinzel title + rule).
- **Active/selected** states tend to be ink fill + cream text (see `MuscleChips`), accents in brass/gold.
- Decorative numbers may render as **Roman numerals** (see helpers in `HomeView`); keep that flourish where established.
- Ornamental art is drawn with **`Canvas`/`Shape`** (`Spire`, `HatchFill`, `DecoLineChart`), not images.

**Reuse before building:** prefer `DecoHeader`, `SectionTitle`, `Kicker`, `DiamondDot`, `.decoCard()`, `MuscleChips`, `DecoSearchField`, `FlexibleWrap`. If you need a new shared piece, add it to `Components.swift`/`Ornaments.swift` so screens stay consistent.

## iOS 16 floor — consequences

Deployment target is **iOS 16** (sideload reach). Do not use iOS 17+-only API. Notably:
- **No Swift Charts** — charts are hand-drawn (`DecoLineChart` in `ProgressTab.swift`). Extend that, don't import `Charts`.
- Wrapping layouts use the **`Layout` protocol** (`FlexibleWrap`), which is iOS 16-fine.
- Stores are `@MainActor ObservableObject` with `@Published`; views use `@EnvironmentObject var store: AppStore`.

## Data model

- Catalog (`Exercise.all`) is **static**. Add exercises there; ids are stable string keys used in saved data and PRs.
- A `Workout` has `[ExerciseEntry]`, each with `[SetEntry]` (`weight`, `reps`, `done`). Dates are stored as `yyyy-MM-dd` strings via `AppDate`.
- Persistence key is `"fg_workouts"` (matches the original web app). If you change the `Codable` shape, handle migration — users have real saved data on-device.
- Demo data seeds only when storage is empty (`AppStore.seedDemoData`).

## Releases / CI — how updates ship

Pushing a **`vX.Y.Z` tag** triggers `.github/workflows/release.yml`, which builds the unsigned IPA, publishes a **GitHub Release** with `FitForge.ipa`, and deploys `apps.json` (a SideStore/AltStore **source manifest**) to **GitHub Pages**. The phone subscribes to that source and gets updates.

```bash
git tag v0.3.0
git push origin v0.3.0     # build + release + Pages update happen automatically
```

Source URL (added once in SideStore): `https://karim-al-shammas.github.io/stone/apps.json`

**Versioning gotcha (already fixed — don't reintroduce):** the app version must come from the git tag. `project.yml`'s `info.properties` sets `CFBundleShortVersionString: "$(MARKETING_VERSION)"` and `CFBundleVersion: "$(CURRENT_PROJECT_VERSION)"`; CI injects `MARKETING_VERSION` (from the tag) and `CURRENT_PROJECT_VERSION` (run number) at build time. If you hardcode a literal version in `Info.plist`/`info.properties`, the IPA's version won't match the manifest and **SideStore will reject the install** ("expected X, got Y"). Bump the **tag**, and keep `project.yml`'s `MARKETING_VERSION` in sync for local builds.

**Infra facts (repo settings, not in code):** repo is public; Pages source = GitHub Actions; the `github-pages` environment has a deployment policy allowing `v*` **tags** (default only allows the main branch); CI runs on `macos-15` + latest-stable Xcode because xcodegen emits project objectVersion 77 (needs Xcode 16+).

## Quick checklist for a UI change or new feature

1. Branch from `swift-native`.
2. Build a screen from existing `Components`/`Ornaments`; pull all colors/fonts from `Theme`.
3. Keep it square-cornered, hairline-bordered, ink-on-cream with brass accents; uppercase letter-spaced mono kickers.
4. Wire any new state through `AppStore` (persist via `save()`); keep models `Codable` and migration-safe.
5. Build for the simulator to verify before committing.
6. After `project.yml` changes, run `xcodegen generate`.
7. Don't introduce paid-account features or iOS 17+ API.
